# React Native / Expo Development Standards

TypeScript rules: `lang-typescript`; component and hook rules: `fe-react`. Platform look and feel:
`design-apple-hig` (iOS), `design-material3` (Android); tokens: `design-tokens`; accessibility
audits: `accessibility`. Native modules in Swift/Kotlin: `mobile-ios` / `mobile-android`.

## Baseline

- Expo SDK 57 is the current stable (React Native 0.86, React 19.2, Node.js 22.13+). SDK 58 is in
  beta on the React Native 0.88 release candidate and targets iOS 27; adopt it once stable.
- Bare React Native: 0.87 is the latest stable. It makes the Strict TypeScript API the default
  (no deep imports from `react-native/Libraries/*`, ref types like `ViewInstance`); the opt-out
  is removed after 0.88 — migrate now.
- New Architecture only (Legacy Architecture removed in RN 0.82 / Expo SDK 55); Hermes V1 is the
  default engine since RN 0.84. There are no architecture or engine flags to set or verify.
- iOS 27 SDK builds need the UIScene life cycle: default in SDK 58; on SDK 57 enable
  `ios.enableSceneSupport` in `expo-build-properties` (expo 57.0.23+).
- Removed in RN 0.87: `InteractionManager` (use `requestIdleCallback`), the `Touchable` root
  export, `StatusBar` `backgroundColor`/`translucent`, `Modal` `animated`. Upgrade with
  `npx expo install expo@latest --fix` then `npx expo-doctor@latest`.

## Project setup

- New apps: `npx create-expo-app@latest` (TypeScript + expo-router template).
- Continuous Native Generation: `ios/` and `android/` are generated by `npx expo prebuild`
  (clean by default since SDK 57) and gitignored. Native changes go through `app.config.ts` and
  config plugins, never hand edits.
- Develop in a development build (`expo-dev-client`), not Expo Go.
- Bare React Native (`npx @react-native-community/cli@latest init`) only for brownfield
  integration; Expo modules still work there.

## Toolchain

- TypeScript `strict` + `noUncheckedIndexedAccess`; `npx expo lint` (ESLint flat config) with
  `no-console`; Prettier; typecheck in CI.
- `npx expo install --check` keeps native packages aligned with the SDK; `npx expo-doctor` in CI.
- `npm audit` / OSV-Scanner on the lockfile; commit the lockfile; one package manager per repo.
- Debug with React Native DevTools (press `j` in the Metro terminal): console, sources,
  React components, profiler, network. Flipper and standalone `react-devtools` are gone.

## Structure

```
app/                         # expo-router routes only: thin files that render feature screens
src/
├── features/orders/
│   ├── domain/              # types, Zod schemas, typed errors, repository interfaces
│   ├── data/                # API/storage adapters implementing domain interfaces
│   └── ui/                  # screens, components, hooks (TanStack Query)
├── platform/                # secure store, push, crash reporting, analytics adapters
└── theme/                   # design tokens, typography, theme provider
```

- Vendor SDKs (`@sentry/react-native`, analytics, payments, Firebase) are imported only in
  `src/platform/` behind interfaces; features import the interface.
- Named exports everywhere except route files, which expo-router requires to default-export.

## Components and styling

```tsx
import { Pressable, StyleSheet, Text } from 'react-native';

import { colors, radii, spacing, typography } from '@/theme/tokens';

type PrimaryButtonProps = {
  label: string;
  onPress: () => void;
  disabled?: boolean;
};

export function PrimaryButton({ label, onPress, disabled = false }: PrimaryButtonProps) {
  return (
    <Pressable
      accessibilityRole="button"
      accessibilityState={{ disabled }}
      disabled={disabled}
      hitSlop={spacing.xs}
      onPress={onPress}
      style={({ pressed }) => [styles.button, pressed && styles.pressed, disabled && styles.disabled]}
    >
      <Text style={styles.label}>{label}</Text>
    </Pressable>
  );
}

const styles = StyleSheet.create({
  button: {
    minHeight: 48,
    justifyContent: 'center',
    borderRadius: radii.md,
    paddingHorizontal: spacing.lg,
    backgroundColor: colors.primary,
  },
  pressed: { opacity: 0.85 },
  disabled: { opacity: 0.5 },
  label: { ...typography.button, color: colors.onPrimary, textAlign: 'center' },
});
```

- `Pressable` for all touchables; never `TouchableOpacity`/`TouchableHighlight` in new code.
- Styles come from `StyleSheet.create` and tokens; no style object literals in JSX. Theme-aware
  styles use a `makeStyles(theme)` factory memoized per theme.
- Dark mode via `useColorScheme()` (returns `null` when unknown) and semantic tokens.
- Edge-to-edge is the norm on Android 15+ and iOS: pad with `react-native-safe-area-context`
  insets, never hard-coded status-bar heights.
- Lists: `FlashList` or `FlatList`, never `ScrollView` + `map`; images with `expo-image`.
- Platform differences: `Platform.select` for values, `.ios.tsx` / `.android.tsx` files when
  behavior diverges.

## Navigation (expo-router)

```tsx
// app/_layout.tsx
import { QueryClientProvider } from '@tanstack/react-query';
import { Stack } from 'expo-router';

import { useSession } from '@/features/auth/ui/use-session';
import { queryClient } from '@/platform/query-client';

export default function RootLayout() {
  const session = useSession();
  const isSignedIn = session.status === 'signedIn';

  return (
    <QueryClientProvider client={queryClient}>
      <Stack>
        <Stack.Protected guard={isSignedIn}>
          <Stack.Screen name="(app)" />
        </Stack.Protected>
        <Stack.Protected guard={!isSignedIn}>
          <Stack.Screen name="sign-in" />
        </Stack.Protected>
      </Stack>
    </QueryClientProvider>
  );
}
```

- File-based routes in `app/`; groups `(app)` / `(auth)`; `Stack.Protected` for auth gating.
- Enable `experiments.typedRoutes` and pass typed `Href` objects for dynamic routes.
- Deep links: set `scheme`, plus associated domains (iOS) and verified intent filters
  (Android) for universal/App Links. Validate route params with Zod in the screen.
- React Navigation 7 directly only in bare apps that do not use expo-router.

## State and data

- Server state: TanStack Query; query functions call repository adapters, never `fetch` inline.
- Client state: Zustand (or React context for small trees). Persist only non-sensitive UI state
  (MMKV or AsyncStorage); session status lives in memory, tokens in `expo-secure-store`.
- Validate every response and env var with Zod at the boundary.

```ts
// src/platform/secure-token-store.ts
import * as SecureStore from 'expo-secure-store';

export interface TokenStore {
  read(): Promise<string | null>;
  write(token: string): Promise<void>;
  clear(): Promise<void>;
}

const REFRESH_TOKEN_KEY = 'auth.refreshToken';

export const secureTokenStore: TokenStore = {
  read: () => SecureStore.getItemAsync(REFRESH_TOKEN_KEY),
  write: (token) =>
    SecureStore.setItemAsync(REFRESH_TOKEN_KEY, token, {
      keychainAccessible: SecureStore.WHEN_UNLOCKED_THIS_DEVICE_ONLY,
    }),
  clear: () => SecureStore.deleteItemAsync(REFRESH_TOKEN_KEY),
};
```

## Errors

- Domain errors are typed (discriminated unions or `Error` subclasses such as `ApiError` with a
  status). Adapters map HTTP, storage, and native-module failures to them.
- Export an `ErrorBoundary` from route files for screen-level fallback UI; the root reports
  unhandled errors through the `CrashReporter` port. Never `catch {}` without handling or logging.

## Security

- Secrets never ship in the bundle: `EXPO_PUBLIC_*` variables and app config are public. Hermes
  bytecode is not obfuscation.
- Tokens only in `expo-secure-store`. OAuth via `expo-auth-session` with PKCE; redirect through
  universal/App Links.
- Validate deep-link params and push payloads before navigating or fetching.
- Certificate pinning, if required, via native configuration or a maintained New-Architecture
  library. Root/jailbreak checks are heuristics — never a security boundary.
- Build-time secrets live in EAS environment variables with `secret` visibility.

## Observability

- A small `logger` module with levels; warnings and errors go to the crash reporter as
  breadcrumbs. `no-console` lint in app code.
- Crash reporting with `@sentry/react-native` (Expo config plugin + `getSentryExpoConfig` in
  Metro for source maps) behind a `CrashReporter` interface; upload source maps for every build
  and EAS Update. `SENTRY_AUTH_TOKEN` as a `sensitive` EAS variable.
- EAS Observe (`expo-observe`) is an option for production performance metrics.

## Performance

- Profile with React Native DevTools before memoizing; stable callbacks for list items.
- Animations with `react-native-reanimated` 4 (worklets) and `react-native-gesture-handler`.
- Defer non-urgent work with `requestIdleCallback`; keep startup work minimal.

## Accessibility and localization

- Follow the `accessibility` skill. Touch targets ≥ 44×44 pt / 48×48 dp (`minHeight` or
  `hitSlop`); `accessibilityRole`, label, state, and hint on custom controls.
- Keep `allowFontScaling` on; cap with `maxFontSizeMultiplier` (≥ 2) only where layout breaks.
- Respect Reduce Motion (`useReducedMotion` from Reanimated or `AccessibilityInfo`).
- `expo-localization` for locale and calendar; `i18next` + `react-i18next` for messages with
  ICU plurals; `Intl` for numbers, dates, currency.
- RTL: keep RTL enabled on the `expo-localization` config plugin (`supportsRTL`; iOS also needs
  the locale in `supportedLocales`), use `start`/`end` style props (`marginStart`, `paddingEnd`),
  and mirror directional icons with `I18nManager.isRTL`. Direction changes need a reload.

## Testing

- Jest with the `jest-expo` preset and `@testing-library/react-native`; query by role and label.
- Mock network at the edge with MSW (`msw/native`); fake platform adapters via their interfaces.
- E2E with Maestro flows on dev or preview builds (Detox for complex gesture timing).

```tsx
import { fireEvent, render, screen } from '@testing-library/react-native';

import { PrimaryButton } from './primary-button';

it('calls onPress when tapped', () => {
  const onPress = jest.fn();
  render(<PrimaryButton label="Submit" onPress={onPress} />);
  fireEvent.press(screen.getByRole('button', { name: 'Submit' }));
  expect(onPress).toHaveBeenCalledTimes(1);
});
```
