# Supply-Chain Security

Covers what you consume (dependencies, actions, base images) and what you ship (SBOMs, signatures,
provenance, publishing). Code-level vulnerabilities: `security-sast`. General pipeline structure:
`devops-cicd`. Container hardening: `devops-docker`.

## Baseline

- Threat model: compromised maintainer accounts, typosquats, hijacked tags, malicious install
  scripts, poisoned CI caches, and stolen publish tokens — not just known CVEs.
- Every consumed artifact is pinned immutably (lockfile hash, commit SHA, image digest).
- Every shipped artifact has an SBOM, a signature, and build provenance, all verifiable by consumers.
- No long-lived publish or cloud credentials in CI: use OIDC (trusted publishing, keyless signing,
  cloud workload identity).
- New releases of dependencies wait a cooldown period before adoption; security fixes are exempt.

## Consuming dependencies

- Commit lockfiles; install with frozen modes in CI: `npm ci`, `pnpm install --frozen-lockfile`,
  `yarn install --immutable`, `uv sync --locked`, `poetry sync` against a committed lock.
- Enforce a minimum release age at both the bot and the package manager:
  - Dependabot: `cooldown` (default 3 days for version updates since July 2026; security updates
    are exempt). Raise majors to 14–30 days.
  - Renovate: `minimumReleaseAge: "3 days"` with `minimumReleaseAgeBehaviour: "timestamp-required"`;
    `config:best-practices` (Renovate 42+) adds npm release-age, action and image digest pinning.
  - npm ≥11.10 `min-release-age=3` (days, `.npmrc`); pnpm ≥10.16 `minimumReleaseAge` (minutes,
    `pnpm-workspace.yaml`); Yarn ≥4.10 `npmMinimalAgeGate` (minutes); uv ≥0.9.17
    `exclude-newer = "3 days"`.
- Block install scripts by default: `ignore-scripts=true` in `.npmrc` (allowlist packages that need
  builds) or rely on pnpm's default build-script blocking; Bun runs dependency lifecycle scripts
  only for `trustedDependencies` and its built-in allowlist.
- Add dependencies deliberately: check maintainers, age, download trend, repository link, and
  provenance (`npm audit signatures` verifies registry signatures and attestations).
- Use a single internal registry proxy (Artifactory, Nexus, CodeArtifact) where available; scope
  private packages (`@org/`) to prevent dependency confusion.

## Pinning

- GitHub Actions: full 40-char commit SHA plus a version comment — tags are mutable (tj-actions,
  Trivy). Let Dependabot/Renovate bump SHA and comment together.
- Container images: `FROM image:tag@sha256:<digest>`; Renovate `docker:pinDigests` keeps them fresh.
- Tools downloaded in CI (`curl | sh`) are forbidden; use pinned actions, package managers with
  lockfiles, or verify a checksum/signature before executing.
- Go: commit `go.sum`; keep the checksum database (`GOSUMDB`) enabled and set `GOPRIVATE` only for
  your own module paths.

## Shipping artifacts

- Generate an SBOM per artifact at build time (not from a later rescan):
  `syft <image@digest> -o cyclonedx-json=sbom.cdx.json -o spdx-json=sbom.spdx.json`.
- Sign by digest, never by tag: `cosign sign --yes registry/app@sha256:...` (keyless via OIDC).
- Attest provenance with `actions/attest@v4` (permissions: `id-token: write`,
  `attestations: write`, `contents: read`); attach the SBOM with `sbom-path`.
- Target SLSA v1.2 Build L3: hosted runners, isolated build job, provenance generated by the
  platform, no user-controlled signing keys.
- Publish packages with trusted publishing (OIDC), not tokens:
  - npm: GA since July 2025, npm ≥11.5.1, GitHub-hosted runners; `repository.url` must match.
  - PyPI: `pypa/gh-action-pypi-publish` with `id-token: write`; PEP 740 attestations are on by
    default; not supported from reusable workflows.
- Consumers verify before deploy: `cosign verify` with `--certificate-identity` and
  `--certificate-oidc-issuer`, or `gh attestation verify --repo org/repo --signer-workflow ...`;
  enforce in-cluster with an admission policy (Sigstore policy-controller or Kyverno).
- Publish VEX documents for CVEs that do not affect you (`vexctl create ... --status not_affected
  --justification vulnerable_code_not_in_execute_path`) and feed them to scanners (`grype --vex`).

## Structure

- Keep supply-chain logic in CI config and policy files, not application code.
- Application code that fetches plugins, models, or updates at runtime goes behind a port
  (`ArtifactVerifier`) whose adapter verifies signature and digest before loading.
- One reusable workflow owns build, SBOM, sign and attest; product workflows call it.

## Errors and incidents

- Verification failure is fatal: never fall back to unverified artifacts or `--insecure-*` flags.
- On a compromised dependency or action:
  1. Identify exposure window and affected runs (lockfile diffs, workflow logs, SBOM search).
  2. Pin to the last known-good version or SHA; purge caches.
  3. Rotate every secret the affected jobs or machines could read — assume exfiltration.
  4. Hunt for persistence (new workflows, deploy keys, npm tokens, SSH keys).
- Lessons encoded in the rules above:
  - tj-actions/changed-files (Mar 2025) and Trivy (Mar 2026): tags force-pushed to malicious
    commits — pin SHAs.
  - Shai-Hulud (Sep and Nov 2025), Nx "s1ngularity" (Aug 2025), axios (Mar 2026): install scripts
    stole tokens and self-propagated — block scripts, cooldowns, trusted publishing.
  - chalk/debug (Sep 2025): maintainer phished — phishing-resistant 2FA, provenance checks.

## Security

- Least-privilege `permissions:` per job (`permissions: {}` at workflow level); no
  `pull_request_target` with checkout of PR code; `persist-credentials: false` on checkout.
- Protect release tags and branches (rulesets), require reviews on workflow changes (CODEOWNERS
  on `.github/`), and use deployment environments with required reviewers for publish jobs.
- Never cache build outputs across trust boundaries (fork PRs must not write shared caches).

## Observability

- Upload SBOMs and scan results (SARIF) to the code-scanning dashboard; alert on new criticals.
- Track Scorecard score over time and fail on regressions in `Pinned-Dependencies`,
  `Token-Permissions`, and `Dangerous-Workflow`.
- Log verification outcomes (artifact digest, signer identity) at deploy time via the logger.

## Testing

- CI gate: dependency review on PRs (`fail-on-severity: high`, `allow-licenses` list).
- Periodically test verification by deploying an unsigned image to staging and confirming the
  admission policy rejects it.
- Validate `dependabot.yml`/`renovate.json` changes (`renovate-config-validator`) before merge.
